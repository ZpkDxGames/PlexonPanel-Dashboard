# PlexonPanel Dashboard / Relay 3.0.2 deployment and live checks

The 3.0.2 control-plane deployment is coordinated with `ZpkDxGames/PlexonPanel` 3.0.2 and remains on wire protocol v3.

## Deployment order

Deploy in this order:

1. Cloudflare relay Worker
2. Dashboard application
3. Paper 3.0.2 JAR, with Minecraft stopped
4. Host 3.0.2 JAR
5. Host systemd unit update
6. Host-only validation
7. Minecraft start from Dashboard
8. repeated lifecycle stress test

Do not rotate identities, delete the shared access registry, or force a browser re-pair as part of the upgrade.

## 1. Relay

From a clean checkout of the reviewed 3.0.2 Dashboard/Relay revision, run the repository checks before deployment:

```bash
npm ci
npm run check
npm run relay:smoke
npm run build
```

Deploy the relay using the repository's configured Cloudflare environment:

```bash
npm run relay:deploy
```

Confirm the deployment completes successfully and inspect Worker logs for sanitized diagnostics only. Logs may include server ID, agent kind, message type, rejection code, session age, and sequence/generation context; they must not contain credentials, private keys, file contents, console contents, chat contents, or bearer tokens.

## 2. Dashboard

Deploy the reviewed 3.0.2 Dashboard revision through the repository's configured Vercel project.

Confirm the browser reports:

```text
PlexonPanel Dashboard 3.0.2 / Protocol 3
```

Do not treat an offline Paper agent as a global control-plane outage when Host is connected.

## 3. Host-only state before Minecraft starts

Before starting Minecraft, the Dashboard must show:

```text
Host: Connected
Paper: Offline
Service: Stopped
```

Expected behavior:

- Host telemetry remains available.
- `server.start` remains available.
- Paper-dependent cards are unavailable rather than stale.
- No global disconnected banner claims Host is offline.

## 4. Start / stop transitions

Starting from Dashboard should transition through:

```text
Host: Connected
Service: Starting
Paper: Connecting
```

then:

```text
Host: Connected
Paper: Connected
Service: Running
```

Stopping should transition through:

```text
Paper: Disconnecting
Host: Connected
Service: Stopping
```

then:

```text
Paper: Offline
Host: Connected
Service: Stopped
```

A failed Dashboard browser send must never disconnect Paper or Host. A failed cross-agent peer send must isolate the failed destination and leave the sender authenticated.

## 5. Cloudflare diagnostic expectations

During the lifecycle test, inspect Worker logs for these sanitized categories when applicable:

```text
INVALID_ENVELOPE
PROTOCOL_MISMATCH
WRONG_SERVER
INVALID_SIGNATURE
INVALID_IDENTITY
SESSION_REPLAY
INVALID_INITIAL_SEQUENCE
CHALLENGE_REJECTED
AUTH_REQUIRED
ACCESS_SYNC_INVALID
HOST_GRANT_CONFLICT
HOST_AUTHORIZATION_CHANGED
INVALID_EVENT
PEER_DELIVERY_FAILED
DASHBOARD_DELIVERY_FAILED
INTERNAL_POST_AUTH_FAILURE
```

A real replay, tampered signature, wrong server, malformed envelope, or invalid authenticated event must still fail closed. A Dashboard fan-out or peer-delivery failure must not be reported as protocol corruption by the healthy sender.

## 6. Browser lifecycle

Close all Dashboard tabs while Paper and Host are connected. Reopen later.

Expected:

- Agent connections remain stable while no browser is open.
- Reopening does not cause `access.sync` churn or a 4008 loop.
- Current state is repopulated automatically.
- Existing device credentials remain valid.

## 7. Twenty-cycle acceptance

Run 20 consecutive Dashboard Stop → Start cycles against the live Linux/Paper deployment.

For every cycle record whether:

- Host stayed authenticated while Paper stopped.
- Start was possible with Host only.
- Paper re-authenticated after startup.
- telemetry resumed without page reload.
- no persistent reconnect/BACKOFF state remained.
- no 4008 loop occurred.
- lifecycle actions stayed available.

The release remains a candidate until all 20 cycles pass.

## 8. Temporary relay/network interruption

Use the deployment environment's normal safe network/Worker interruption test.

Expected:

- browser can display reconnect/stale state without falsely declaring the service stopped.
- Paper and Host recover automatically after connectivity returns.
- no identity reset or re-pair is required.

## Release gate

Keep the PR/release in draft until the automated suite and the coordinated live checklist in the PlexonPanel repository are both complete. CI success alone is not sufficient evidence for the control-plane lifecycle requirement.
