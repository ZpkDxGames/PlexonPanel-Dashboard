# Dashboard and relay 4.0 source audit

Audit baseline: Dashboard `main` at `5d25671bc73569e18599be1e9034291d1f87d171`, with the reviewed
changes from PRs #50 and #51 carried by exact commits.

## Reviewed surfaces

- Next.js 16 App Router boundaries, client state ownership, build route and metadata.
- Pairing/session validation, IndexedDB credential storage, scope/capability intersection,
  confirmations, reconnect/heartbeat handling and stale-socket rejection.
- Overview, Players/history, Console/history, Backups/maintenance, Settings/build identity,
  responsive styles, accessibility states and bounded long-session collections.
- Worker and standalone protocol validation, signatures, replay, rate/size bounds, routing,
  Durable Object/SQLite coordination, dead-session cleanup and parity tests.
- Lockfile, lint/typecheck/tests, Worker dry run, standalone smoke/package, production build and
  deployment workflow.

## Findings and disposition

| Severity | Finding | 4.0 disposition |
| --- | --- | --- |
| Critical | Pinned Next.js 16.3.5 is affected by the package advisory reported as `GHSA-vcvr-r3jv-pc5j`. | Pin Next.js and its ESLint config to 16.3.8 and re-run audit/build/tests. |
| High | Relay builds mutated checked-in source through historical preparation scripts. | 4.0 builds compile canonical checked-in sources; preparation only regenerates the checked scope contract. |
| Medium | Version identity was distributed across package, UI, relay and tests. | Synchronized to 4.0.0 with build-identity contract tests. |
| Medium | Retained console/player history was split across stacked work. | Integrated exactly, keeping bounded pagination and mixed-version fallback. |
| Low | Baseline lint reported unused adapter/overview symbols and a dynamic avatar image warning. | Remove unused symbols; document the constrained dynamic-avatar exception or adopt a safe loader. |

## Verification status

Before 4.0 edits, `npm run check`, Worker smoke, standalone smoke/package, and `next build` passed:
67 relay tests and 109 Dashboard tests. These are baseline results only. The full suite, production
build, package audit, and deployment identity checks must pass again on the exact 4.0 commit.
Runtime and production deployment certification remain separate gates.
